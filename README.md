# dsh-nio-memo — 全局「手记」插件

> **一句话**：把「记忆卡片」从对话记忆系统里剥离出来的**极简卡片库插件**——全局部署、零依赖、无 LLM；卡片可以**每轮注入**，也可以**按需取用**，还可以挂上**多档位的软权限**。
>
> 当前版本：**v1.0.0（首个发布版，只含默认卡片集）** ｜ 归属项目：zt工坊 `nio-memo`

## 一、它解决什么问题

传统做法把「记忆卡片」塞在对话记忆系统里（跟切块、提炼、检索、上下文治理搅在一起），结果是：

- 卡片功能被上层系统绑架，改一处要考虑三处；
- 卡片会随系统一起膨胀（分层、分发、同步、版本头…），越来越重；
- 想要「几张必须记住的规矩 + 一堆按需查阅的资料」这种简单诉求，反而没有轻量的落法。

**dsh-nio-memo 的做法**：把卡片单独拿出来，做成一个**只做卡片**的插件：

- **全局**（不绑项目目录，任何会话都生效）
- **零依赖**（`node:sqlite`；无 LLM、无后台 worker、无同步）
- **注入面可控**：必须遵守的每轮注入；资料类只注入一行索引，命中才取全文

## 二、核心概念

### 2.1 实体与所在区

| 实体 | 所在 | 注入行为 |
|---|---|---|
| **铁律条例**（`iron_clauses`） | 规矩页 | **锁死**：正文不可编辑、不可删除，每轮**无条件全文注入**（但**档位可编辑**，见 2.3） |
| **动态规矩卡**（`cards.state='rule'`） | 规矩页 | 启用时每轮**全文注入**；可关闭、可降为备忘 |
| **备忘卡**（`cards.state='memo'`） | 备忘页 | 默认只把「卡片名 / 关键词 / 路径」注入**索引清单**；命中关键词时由 agent 用工具取全文 |
| **权限板块**（`perm_levels`） | 横切：任何实体都能挂 | 见 2.3 |

### 2.2 来源：默认 / 自定义

- **默认**（`origin='default'`）：**官方维护**的卡片。将来把本项目提交公共库时，**只提取默认部分**。
- **自定义**（`origin='custom'`）：使用者自己建的（手动创建、agent 创建，都算自定义）。

两者**功能完全一致**，只用于排序（默认在前）、着色（默认=蓝 / 自定义=绿）与公共库抽取。
「默认 / 自定义」同时是**系统标签**（不可改名、不可删除；计数按来源自动统计）。

### 2.3 权限板块（软约束 · 内测）

任何实体（**含铁律**）都能开启「权限板块」：

- **默认关闭**（灰色）。开启后该实体拥有自己的**档位**：默认两档 `禁止`=赤 / `允许`=蓝；可改名、可加档、可删档（至少留一个）、可配色（黑/白/灰/赤/橙/黄/绿/青/蓝/紫，允许不同档位同色）。
- **只注入当前档位**：注入时随实体内容一起附上「当前档位：X」与该档位内容。
- **开启权限 = 改注入口径**：备忘卡一旦开启权限，就从「只注入索引清单」变为**全文注入**（权限只有被看到才有效）。
- 卡面：开启权限的实体，底部**直接显示当前档位名**（文字用档位颜色），点它即可切换；关闭时不显示档位按钮。
- 内页：板块固定在**页面最底部**、默认**收起**，点「展开」才编辑档位。

> ⚠️ **权限只是软约束**：它写进提示词、约束 agent 的行为预期，**不保证 agent 一定遵守**（模型仍可能越界或忽略）。关键红线请另配外部手段兜底（人工复核 / 工具闸门 / 权限系统）。
> 「权限板块」标注为**内测**：字段、交互与注入口径都可能变动。

### 2.4 标签 / 回收站 / 版本号

- **标签**：自定义标签可增改删；卡片可打标；标签页可按标签**批量转移（规矩↔备忘）、批量启用/停用、批量删除**。系统标签「默认 / 自定义」不可改删。
- **回收站**：删除是**软删除**（`deleted_at`）。站内可**恢复**或**彻底清除**（不可恢复），**不可编辑**；回收站里的卡片不参与注入。
- **版本号**：每张卡有整数版本（显示为 `v1.0`、`v2.0`…）。创建/编辑表单可手填；不填则编辑自动 +1（启停、升降区、打标**不**改版本）。卡面只显示日期，完整时间在内页与悬浮提示里。

## 三、界面与交互

### 3.1 主 Tab（会话页）

```
手记
├── 规矩   铁律（锁死） + 动态规矩（默认/自定义分组）
├── 备忘   卡片（默认/自定义分组，可开权限板块）
└── 设置   创建 / 标签 / 回收站
```

### 3.2 卡面

- **标题**：一行，超出省略
- **关键词**：最多两行
- **底部标签行**：来源（默认/自定义）、动态 / 已停用、自定义标签
- **卡外底部**：按钮一行（`停用/启用`、[当前档位名]、`更多`），**日期另起一行小字**（不与按钮同行）
- **不显示路径**（路径在内页与注入索引里给 agent 用）
- 同排卡片**高度一致**（卡高固定，内容超出省略）

「更多」悬浮菜单（按屏幕空间自动换向：默认右下 → 右侧不够则左下 → 下方不够则上移）：`打开 / 立为规矩·降为备忘 / 打标 / 更新 / 复制 / 删除`。
（`更新` 只刷新修改时间；`复制` 生成自定义副本，标题后缀 `_副本`。）

### 3.3 内页

- 正文（Markdown 渲染：标题 / 列表 / 引用 / 表格 / 代码块 / 分隔线 / 行内码 / 链接）
- 关键词、路径、`v版本 · 改于 时间`
- 操作：停用/启用、立为规矩/降为备忘、编辑（名称 / 关键词 / 标签 / 正文 / **版本号**）、复制、打标、删除
- 编辑**默认卡**时会提示：不建议直接改（会与源头分叉），建议「关闭它」或「复制成自定义卡再改」
- **底部**：权限板块（独立区块、虚线分隔、默认收起）
- **铁律内页**：正文锁死（无编辑入口），但**权限板块可编辑**

## 四、注入口径

每轮由宿主把下列段落拼进系统提示词（`<nio-memo>` 包裹；**实时读库**，改完立即生效、无需重启）：

| 段 | 内容 | 条件 |
|---|---|---|
| 规矩 · 铁律 | 条例**正文**（+ 若开权限：当前档位名与档位内容） | 全部、无条件 |
| 规矩 · 动态规矩 | 卡片**全文**（+ 若开权限：当前档位） | `enabled=1` |
| 备忘（已开启权限） | 卡片**全文** + 当前档位名与内容 | `enabled=1` 且 `perm_enabled=1` |
| 备忘 · 索引 | 一行一条：`- 卡片名 ｜ 关键词：a、b ｜ 路径：…` | `enabled=1` 且未开权限 |

- 停用的卡片不进任何注入段；为免「静默消失」，注入末尾会显式写明「另有 N 张卡片已停用，未注入」。
- 注入失败**不静默**：会在提示词里插入显式告警行。

> 📏 **成本提示**：注入体积随卡片数增长（默认集约 3K 字符/轮；大量导入后可到 8K+）。想瘦身就按标签批量停用不常命中的卡片。

## 五、数据模型

库文件：`$DSH_HOME/nio-memo/memo.db`（默认 `~/.dsh/nio-memo/memo.db`；环境变量 `NIO_MEMO_DIR` 可整体覆盖）。
引擎：Node 内置 `node:sqlite`（WAL + `busy_timeout=5000`）。

| 表 | 用途 | 关键列 |
|---|---|---|
| `iron_clauses` | 铁律条例 | `title` `path`(唯一) `content` `origin` `perm_enabled` `perm_current` |
| `cards` | 卡片（备忘 / 动态规矩同表双态） | `name`(唯一) `path`(唯一) `state` `enabled` `origin` `content` `version` `deleted_at` `perm_enabled` `perm_current` |
| `perm_levels` | 档位（挂在实体上） | `owner_kind`(card/iron) `owner_id` `name` `content` `color` `pos` |
| `tags` | 标签 | `name`(唯一) `system`(1=系统标签) |
| `card_tags` | 卡片×标签 | `card_id` `tag_id` |
| `perm_tags` / `permissions` / `permission_levels` | **旧版「权限卡实体」**（仅留档，新代码不再写入） | — |
| `meta` | 元信息 | `seed_version` `origin_v1` `origin_v2` `perm_merged_v1` `index_note` |

**路径规则**：`备忘/<卡名>.md`、`规矩/动态/<卡名>.md`（改名会同步更新路径）。路径既是给 agent 的读取键，也是 `nio_memo` 工具的参数。

**自动迁移**（打开库时执行，幂等）：

- 补列：`origin` / `version` / `deleted_at` / `perm_enabled` / `perm_current` / 档位 `color`
- 一次性回填来源（`meta.origin_v1`、`origin_v2`）
- 旧「权限卡实体」并入实体：`是否允许 agent 自行添加手记卡片` → 铁律「手记卡片维护」；`是否允许 agent 自行重启 DSH` → 卡片「DSH重启方式」（`meta.perm_merged_v1`）

## 六、安装与部署

### 6.1 前置

- DSH（Web）可用；Node ≥ 22.5（需要内置 `node:sqlite`）
- 宿主包由 DSH 提供：`@deepseek-ai/cordis`、`@deepseek-ai/dsh-tools`

### 6.2 安装（开发态 link 安装）

```bash
# 1) 把插件挂进 profile
ln -s /path/to/nio-memo ~/.dsh/profiles/web/node_modules/dsh-nio-memo

# 2) profile 的 package.json 里，dsh.profile.bundles 增加一行：
#      "dsh-nio-memo"

# 3) 重启 DSH 生效
systemctl restart dsh.service
```

> ⚠️ 重启会 **SIGTERM 整个 cgroup**：会话内后台任务（含各类哨兵/订阅进程）会被一并杀掉且**无通知**，需要各自重挂。**重启宿主服务须取得授权**（本项目立场）。
>
> 改 **host 端**（`src/*.ts`）→ 重启生效；改 **client 端**（`client/*.tsx`）→ 重建 `lib/client.js` 后重启 **+ 浏览器硬刷新**（Ctrl/Cmd+Shift+R），否则看到的仍是旧 bundle。

### 6.3 本机开发/测试的依赖软链

插件运行时**不带** `node_modules`（依赖由宿主提供）；但本机跑构建/测试需要：

```bash
mkdir -p node_modules/@deepseek-ai
ln -s <DSH 检出>/vendor/cordis         node_modules/@deepseek-ai/cordis
ln -s <DSH 检出>/packages/core/tools   node_modules/@deepseek-ai/dsh-tools
# 仅 SSR 测试用：
ln -s <DSH 检出>/node_modules/.pnpm/react@*/node_modules/react         node_modules/react
ln -s <DSH 检出>/node_modules/.pnpm/react-dom@*/node_modules/react-dom node_modules/react-dom
```

## 七、日常使用

| 想做的事 | 怎么做 |
|---|---|
| 记一条资料 | 设置 → 创建（或直接让 agent 记，更省事）；落「备忘」 |
| 让某条每轮都生效 | 卡片「更多 → 立为规矩」；或让 agent 写成动态规矩 |
| 临时静音一张卡 | 卡面「停用」（启用卡排前面，停用卡自动沉到组末） |
| 改卡 | 内页「编辑」（含版本号）；默认卡建议复制后再改 |
| 批量处理 | 设置 → 标签 → 点标签 → 批量转移 / 批量启用·停用 / 批量删除 |
| 删错了 | 设置 → 回收站 → 恢复；确认不要了再「彻底清除」 |
| 给 agent 一个可切换的行为约束 | 内页底部「权限板块」→ 开启 → 编辑档位（禁止 / 允许…） |

## 十、默认卡片集

本版本**只发布默认集**（`origin='default'`）；自定义卡片**不进仓库**、**不进 seed**。全新安装后的库内容：

| 区 | 条目 | 说明 |
|---|---|---|
| 铁律 | **手记卡片维护** | 写卡触发点（记住这个 / 这是铁律 / 明确纠正 / 可复用新事实 / 同一问题第二次 / 偏好口径）+ 落位口径（**默认从严**：除非你说「这是规矩」，否则只能落备忘）+ 维护口径；**自带权限板块**（禁止 / 允许，默认「禁止」＝agent 不得自行加卡） |
| 动态规矩 | **禁止静默兜底**、**失败显式化**、**改动前备份**、**交互性决策** | 4 条默认规矩，每轮全文注入 |
| 备忘 | **Tailscale组网**、**本机主机102**、**DSH重启方式** | 前两张是样板卡；`DSH重启方式` 是通用版重启手册（含编号纪律、连坐杀哨、硬刷新），**自带权限板块**（禁止 / 允许，默认「禁止」＝重启前必须先取得授权） |

> 旧系统的其余手记卡（49 张）属于**使用者数据**：可用 `scripts/import-cards.ts` 在本机导入（全部落为「自定义」），**不随本仓库分发**。

## 十一、已知限制与注意事项

1. **权限是软约束**，不保证模型遵守；红线请外置兜底。
2. **权限板块为内测**：字段 / 交互 / 注入口径可能变动；「设置 → 标签」的批量操作与计数**不含**权限卡（权限已并入实体，其标签在实体内页管理）。
3. **注入体积**随卡片数增长（默认集约 3K 字符/轮；全量导入后 8K+）。瘦身手段：按标签批量停用。
4. **路径含卡名**：改名会同步改路径（`nio_memo` 的读取键随之变化，旧路径引用会失效）。
5. **重启必须授权**：DSH 重启会 SIGTERM 整个 cgroup，会话内后台任务（含工坊哨兵）会被杀掉且无通知。
6. **脚本源路径**：`gen-seed.mjs` / `import-cards.ts` 里的真源路径按 102 本机写死，换机需改。
7. **备份增长**：两个脚本会自动备份库文件并**保留最近 5 份**。

**开发纪要（踩过的坑，写下来省得再踩）**

- JSX 里写 `{n}` 会被当**表达式**求值 ⇒ 运行期 `ReferenceError` ⇒ **内页白屏**；要在文案里显示花括号必须写成字符串字面量。
