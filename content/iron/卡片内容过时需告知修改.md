## 卡片内容过时需告知修改

> **铁律（锁死 · 每轮无条件注入）** · v2 · 2026-10-16
> 沿革：v1 为动态规矩《发现卡内容过时：先告知用户，获准后再改》（手记卡 id 97，2026-10-16 建）；据用户 2026-10-16 指令**升为铁律并更名为本标题**，条文内容不变，此后锁死、不可停用。

### 正条

发现**任何手记卡片**（备忘 / 规矩 / 角色 / 经验）的内容**已过时或与事实不符**时：

1. **立马告知用户**（无条件义务）——同一条回复里点明：**哪张卡、哪一句、为什么过时、当前正确口径是什么**（附证据/出处）。⛔ 不许只在心里记下、更不许继续把错卡当依据用。
2. **修改前必须取得用户准许**——拿到"改吧 / 准许"之类明确授权后才动手；⛔ 不得以"反正是错的"为由自行改卡。
3. 获准后**用手记原生方式改**（`updateCard`，⛔ 勿直接写 SQL），并遵守既有纪律：**改前 `VACUUM INTO` 备份**、版本 +1、**改后告知**（改了哪张、改了哪句）。
4. 若该卡是**通用记忆分发副本**（卡内自述「本机勿改 / 会被下一次分发覆盖」）⇒ 除本地手记卡外，**必须同时/优先修真源**（如 `000_dsh/项目/通用记忆/发布vN/...`），否则下一次分发会把错文推回来；**是否向各主机分发由用户定**。
5. 若发现的是**历史记录**（记录"当时发生了什么"）⇒ **不改写历史**，只在其后加 `⚠ 口径更新（日期）` 标注，指明已被哪条新口径取代。

### 边界

- 本条约束的是"**改卡**"；**告知义务无条件**——不管用户准不准许，"发现即报"。
- 与铁律《手记卡片维护》一致（写/改卡都要告知）；本条把"**内容过时**"这一情形显式化，并加上"**须先获准**"这道闸。
- 与动态规矩《通用卡片只许「整理」时新增》不冲突：那条管"**新增/提炼通用卡**"，本条管"**已有卡内容错了要改**"。

### 判据一句话

*发现卡过时 → 立刻告诉用户 + 说清错在哪 + **等他点头** → 再改（留痕；必要时连真源一起改）。*
